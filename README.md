# Контрольная точка 13: жадные алгоритмы, быстрый выбор, кэш LFU

Практикум по алгоритмам. Шесть задач, решения на Java.

| № | Задача | Класс | Подход | Время | Память |
|---|---|---|---|---|---|
| 1 | Заявки на один зал | `Bookings` | жадно по раннему концу | O(n log n) | O(n) |
| 2 | Журнал с минимумом и максимумом | `MinMaxStack` | стек с минимумом и максимумом в каждом элементе | O(1) на команду | O(q) |
| 3 | Значение на позиции k | `KthElement` | быстрый выбор, разбиение на три части | O(n) в среднем | O(1) |
| 4 | Заказы со сроками | `Orders` | по срокам + куча по прибыли | O(n log n) | O(n) |
| 5 | Кэш вместимости C | `LfuCache` | списки ключей по частотам | O(1) в среднем на команду | O(C) |
| 6 | Первые k пунктов | `ClosestPoints` | буфер на 2k + быстрый выбор | O(n + k log k) в среднем | O(k) |

## Запуск

Нужен JDK 17 или новее, Gradle скачается сам через wrapper.

```
gradlew test                          # тесты
gradlew run -q --args="5" < input.txt # задача 5, ввод из файла
```

Номер задачи передаётся аргументом, входные данные читаются из stdin в формате
из задания, ответ печатается в stdout. Например, для задачи 5:

```
2 9
PUT 1 1
PUT 2 2
GET 1
PUT 3 3
GET 2
GET 3
PUT 4 4
GET 1
GET 4
```

ответ `1`, `-1`, `3`, `-1`, `4` по одному в строке.

На Windows проект лучше держать в папке без кириллицы в пути. Иначе Gradle
не находит тестовые классы (`ClassNotFoundException`), хотя они скомпилированы.

## 1. Заявки на один зал

Заявки перебираются по возрастанию конца, берётся каждая, которая начинается
не раньше конца последней взятой. Почему это верно: заявка с самым ранним концом
освобождает зал раньше всех. В любом оптимальном наборе первую заявку можно
заменить на неё, ничего не сломав, и дальше рассуждать так же для оставшегося
времени.

Промежутки полуоткрытые, поэтому заявка `[5, 10)` совместима с `[0, 5)`:
условие взятия `l >= конец последней`, а не строго больше. Для сортировки конец
и начало упакованы в одно число `long` (конец в старших битах), это быстрее
сортировки объектов.

## 2. Журнал с минимумом и максимумом

Вместе с каждым значением хранятся минимум и максимум всего журнала на момент
его добавления: `min[i] = min(min[i - 1], x)`, с максимумом так же. После POP
вершиной становится предыдущий элемент, а его минимум и максимум посчитаны
ещё тогда, когда ниже него ничего не менялось. Так что MIN и MAX просто читают
вершину.

Условие требует O(1) в худшем случае, а не в среднем. Расширяемый массив
(как в `ArrayList`) иногда копирует всё содержимое, поэтому массивы выделяются
сразу на q элементов: больше q значений в журнале быть не может.

## 3. Значение на позиции k

Быстрый выбор. Берётся случайный опорный элемент, массив за один проход
разбивается на три части: меньше опорного, равные ему и больше. Позиция k
попадает ровно в одну часть. Если в среднюю, ответ это опорное значение,
иначе работа продолжается только в нужной крайней части.

Случайный выбор опорного нужен, чтобы никакой вход не давал худший случай
стабильно. В среднем каждый шаг отрезает постоянную долю диапазона, и суммарная
работа `n + n/2 + n/4 + ...` даёт O(n). Разбиение на три части нужно для
повторов: при обычном разбиении на две части массив из пяти миллионов
одинаковых чисел обрабатывался бы за O(n²).

Рекурсии нет, хранятся только границы текущего диапазона, поэтому дополнительная
память O(1). Массив меняется на месте, условие это разрешает.

## 4. Заказы со сроками

Набор заказов можно выполнить, если для каждого момента t заказов со сроком
не больше t не больше t. Тогда их достаточно выполнять в порядке сроков.

Заказы перебираются по возрастанию срока, взятые лежат в куче с минимальной
прибылью наверху. Очередной заказ сначала берётся. Если взятых стало больше,
чем его срок, условие нарушено, и из кучи выбрасывается самый дешёвый заказ.
Выбрасывается всегда наименьшая прибыль, поэтому в куче остаётся самый дорогой
выполнимый набор среди уже просмотренных заказов.

Сроки бывают до 10^9, но слотов больше n не понадобится, поэтому по слотам
ничего не перебирается и массив слотов не заводится.

## 5. Кэш вместимости C

Для каждой частоты хранится список ключей с этой частотой в порядке последнего
использования (`LinkedHashSet` помнит порядок добавления). При использовании
ключ переходит из списка своей частоты в конец списка частоты на 1 больше.
Его момент использования самый поздний из всех, поэтому конец списка для него
верное место. Вытесняется первый ключ из списка наименьшей частоты: у него
и частота минимальная, и последнее использование самое раннее.

Наименьшую частоту не нужно искать. Новый ключ делает её равной 1, а при
использовании ключа она растёт на 1, только если список этой частоты опустел.
Все действия это операции с хэш-таблицами, O(1) в среднем.

Как понято условие:

- GET отсутствующего ключа выводит -1 и ничего не меняет;
- PUT существующего ключа заменяет значение, увеличивает частоту и обновляет
  момент использования, ничего не вытесняя;
- PUT нового ключа при заполненном кэше сначала вытесняет ключ, потом добавляет
  новый с частотой 1.

## 6. Первые k пунктов

Полная сортировка двух миллионов пунктов это O(n log n), а куча на k элементов
даёт O(n log k), условие же требует O(n + k log k) и памяти O(k).

Пункты проходят через буфер на 2k номеров. Когда буфер заполнен, быстрым
выбором в его начало собираются k лучших, остальные k отбрасываются. Среди
отброшенных нет ни одного из k лучших вообще: каждый из k оставшихся лучше
любого из них. Отбор стоит O(k) в среднем и случается не чаще раза на k новых
пунктов, всего O(n). В конце ещё один отбор и сортировка k оставшихся,
O(k log k). Дополнительно после каждого отбора k-й лучший пункт становится
порогом, и пункты хуже него в буфер даже не попадают.

Порядок сравнения из условия: `x² + y²`, затем x, затем y, затем номер. Номера
у всех разные, поэтому двух равных пунктов не бывает, и ответ однозначен даже
для совпадающих координат. При координатах до 10^9 по модулю сумма квадратов
не больше `2 * 10^18` и помещается в `long`, квадраты считаются в `long`.

Координаты всех пунктов хранятся в двух массивах `int`, условие не считает их
в дополнительную память. Номера в выводе с 1, как в условии.

## Тесты

- на каждую задачу граничные случаи и сверка с простым решением на случайных
  входах: перебор подмножеств для задач 1 и 4, `Arrays.sort` для задач 3 и 6,
  список с поиском минимума перебором для задачи 2, кэш с вытеснением
  перебором для задачи 5;
- входы максимального размера из ограничений с таймаутом 5 секунд, в том числе
  пять миллионов одинаковых чисел для задачи 3;
- `MainTest` проверяет чтение ввода и формат вывода для всех шести задач.
